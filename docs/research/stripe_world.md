## Architecture

A Seahaven world implementing Stripe's Billing and Payments core: "155 Stripe API operations
across 24 tables, pinned to API version `2026-08-26.dahlia`" (README; table count not re-counted).
Packages: `schema/` (5 SQL files), `resources/`, `billing/`, `dispatch/`, `http_api/`,
`middleware/` (`idempotency.py`, `stripe_envelope.py`, `error_handler.py`), `tools/` (Stripe MCP
tool surface), `spec/` (pruned Stripe OpenAPI, MIT), `serialize/`, `search/`.

## Core abstractions

Seahaven tables + handlers per Stripe operation id (`PostCustomers`, …); two front doors over one
state: Stripe's HTTP API (`serve_http.py`, SDK-compatible under `/worlds/{id}/`) and Stripe's own
MCP tools (`stripe_api_write`, `list_available_accounts_or_orgs`).

## Execution model

HTTP → Seahaven route → idempotency middleware → envelope → operation handler → SQL → change log
→ Stripe-shaped JSON (validated against the OpenAPI spec in tests).

## State model

Seahaven SQLite per account/instance; fixtures (`fixtures/`, generated by `fixtures_src/generate.py`).

## Fidelity evidence

- Conformance: "recordings of real Stripe API sessions are replayed against it in CI"
  (`tools_dev/record.py`, `tools_dev/scenarios/s01…s13`).
- Our probe: over-refund rejected with "Refund amount ($50.00) is greater than unrefunded amount
  on charge ($40.00)"; card tokens on the Charges API refused with Stripe's real end-of-life
  message.
- Tests: 1,104 passed, 2 skipped locally.
- **Missing:** "Webhook delivery ❌ events are queryable" (README table).
